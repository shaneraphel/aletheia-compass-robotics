# Weight-realized blocked Gram coding: strategy and evidence

This directory releases one complete, executable coding experiment: a DeepSeek-R1-Distill-Qwen-1.5B derivative generated a Python implementation of `blocked_gram_dual_route`, and the generated file passed the unchanged `official_tests.py`. This is evidence for **one task only**, not a leaderboard result, a general coding claim, or autonomous mathematical discovery.

## Mathematical strategy

Let \(X_c=X-\bar X\), \(G=X_cX_c^\top\), and \(J=I-\mathbf 1\mathbf 1^\top/n\). With

\[
D_{ij}=\max(\lVert x_i\rVert^2+\lVert x_j\rVert^2-2G_{ij},0),
\]

the centered Gram/distance dual route satisfies

\[
G=-\tfrac12JDJ.
\]

Expanding the centering operator gives row moments \(r\) and scalar moment \(\mu\), so each row block can independently form \(G_B=X_{c,B}X_c^\top\), \(D_B\), and \(H_B=-\tfrac12(D_B-r_B-\mathbf 1r^\top+\mu)\). The implementation accumulates \(\max|G_B-H_B|\) without constructing `np.eye(n)`, a second full Gram matrix, or the dense `J@D@J` product. Every positive integer block size follows the same block partition, including `block_size > n`.

The model-side realization used measured cotangent entities, a joint dual-cell minimum-Frobenius lift at layer 26, and strict BF16-cell transport through secant updates. No AdamW optimizer, candidate scoring, answer lookup table, or post-generation code repair was used. Mathematical target construction and weight realization were explicitly supervised; the released Python source itself was generated by the model and was not edited by the supervisor.

- Generation budget: **1024 new tokens**; actual generation: **617 tokens**, ending at EOS.
- Frozen candidate SHA-256: `95c9ab974748271ae5679c15e53601e7513c25593579a6578b0874c34c7cf4ab`.
- Unchanged test SHA-256: `d59b18597bd5d023921accae28168d8f485265777e06c8764bc7bc453fdae7b4`.
- Test result: **passed**, exit code 0; **16** random/repeated-point block cases and all specified invalid-input contracts passed.
- Maximum dense-or-blocked identity error: **1.5987211554602254e-14**.
- Unmodified-base comparison: **857 generated tokens**, then the unchanged test failed with `ValueError`; see `baseline_test_receipt.json`.
- Entity realization audit: **248/248** target tokens were top-1 and BF16-cell exact. The 327-token source prefix and its terminal hidden state were preserved exactly. Maximum activation error was 0.0; the recorded maximum FP32 increment discrepancy was 1.1920928955078125e-07.
- Public regeneration with `down_proj_delta.pt` reproduced the frozen candidate byte-for-byte and passed the tests again; see `public_reproduction_receipt.json`.

The result does not establish improvement on other prompts, FATE-X, FrontierMath Erdős, CLEVER, robotics, or any public leaderboard.

## Verify in seconds

Only Python and NumPy are needed:

```bash
cd evidence/gram_coding
python reproduce.py
```

This executes the original, unmodified test file against the frozen model-generated `candidate.py`. It does not write or repair the candidate.

## Regenerate from weights

Obtain `deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B` separately and keep its upstream license. Install the environment recorded in `environment.json`, then run on the recorded Apple MPS setup:

```bash
cd evidence/gram_coding
python reproduce.py --generate \
  --model /path/to/DeepSeek-R1-Distill-Qwen-1.5B \
  --delta down_proj_delta.pt \
  --out ./reproduction \
  --max-new-tokens 1024
```

The script uses the official Transformers model trunk, replaces only layer 26's down projection with the FP32 sum of the original weight and the public total increment, and performs the official linear readout in FP32. It contains no handwritten Qwen2/RoPE forward. Greedy decoding uses the exact FP32 maximum with minimum-token-ID tie breaking. A successful reproduction must both pass the tests and match the frozen candidate hash.

`down_proj_delta.pt` is a compact public container containing the **total** FP32 increment tensor with shape `(1536, 8960)`. Its SHA-256 is `4e7913f516cde7e5064eecdcb9e57e0e23ca6139f8839ee78a42d9ce84169f7b`. The tensor was checked with `torch.equal` against the original experiment container, whose SHA-256 was `91d93069be5e941f60c56989b56bb839ac7fc94eb34dee5df6b7ae89df320b56`. The original container additionally stored a duplicate incremental tensor; that redundant copy is not distributed. Do not apply another base delta on top of this public total increment.
